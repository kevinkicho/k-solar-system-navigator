# Dense SPICE storage budget (HELIOS)

> **HISTORICAL DESIGN** � As-built product: industrial preliminary (not classroom). See [docs/README.md](./README.md).

All table sizes assume **Float32 LE** parent-relative or heliocentric **xyz** (3 floats/sample).
JSON text is ~2–3× larger than binary; prefer `.bin` for dense packs.

## Formula
```
nSamples ≈ spanYears × 365.25 × 1440 / stepMinutes + 1
bytes    = nBodies × nSamples × 3 × 4   (Float32)
```

## Cadence vs accuracy (rule of thumb)
| Body class | Period class | Min samples/orbit | Typical step |
|------------|--------------|-------------------|--------------|
| Phobos | 7.7 h | ≥40 | **10 min** |
| Deimos | 30 h | ≥40 | **30–45 min** (10 min safer) |
| Luna | 27 d | ≥40 | **6–12 h** (30 min overkill OK) |
| Galilean | 1.8–17 d | ≥40 | **30–60 min** |
| Planets | months–years | cubic DE | **1–3 d** (2 d DE440s OK for km-class helio) |

### Bottom line

- **Browser-shipped dense SPICE (Tier A): ~10–25 MiB** — enough for planets (DE 2 d) + Mars moons (10 min) + Luna (30 min).
- **Major-moon tours (Tier B lazy): ~50–80 MiB** — add Galileans + Titan/Triton at 15–60 min over 10 y.
- **“All catalog @ 10 min for 20 y”: ~0.45 GiB** binary — too large for default SPA cold-load; use lazy packs or local.
- **1-minute full catalog 40 y: ~9 GiB** binary — research/desktop only.
- **Live NAIF kernels for all satellites: multi-GiB to tens of GiB** — not for in-browser `.bsp` load.
